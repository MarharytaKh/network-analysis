# net-verify

Проверочные тесты по сетевому трафику. Снимаю трафик в wireshark, потом
скриптом `analyzer.py` достаю из pcap цифры (DNS, TCP, TLS, SIP), а результаты
оформляю отдельными отчетами в `reports/`.

## Структура

```
net-verify/
  analyzer.py        парсер pcap, считает статистику
  captures/          сюда кладу pcap из wireshark (в git не класть, большие)
  reports/           отчеты по тестам
    _template.md     шаблон отчета
    TEST-01-dns.md
    TEST-02-tls.md
    TEST-03-sip.md
```

## Как пользоваться

1. Запускаю захват в wireshark, гоняю сценарий теста, останавливаю.
2. Сохраняю как **pcap** (не pcapng!) в `captures/`.
3. `python3 analyzer.py captures/test01.pcap --json reports/test01.json`
4. Цифры переношу в отчет по шаблону.

Python 3.8+, сторонних библиотек не нужно.

## Что умеет / не умеет

- умеет: pcap (libpcap), ethernet + один vlan, ipv4, tcp/udp
- DNS: кол-во запросов/ответов, qtype, rcode, RTT по (client, tid)
- TCP RTT: грубо, считаю от сегмента с данными до ack с нужным номером.
  Без учета ретрансмитов, так что хвост (p95+) может врать
- TLS: ищу handshake-записи по байтам (0x16 0x03), SNI не вытаскиваю
- SIP: только plain text, только заголовки `Call-ID` и `CSeq`.
  Компактные формы (`i:`) вроде понимаю, но проверено мало

## Заметки / что не сделано

- pcapng не поддерживается. Если wireshark сохраняет pcapng, пересохрани как pcap
- ipv6 пока пропускается (считается как non-ipv4), надо добавить
- SIP over TLS (5061) не смотрю
- TLS-рукопожатие ищется на любом порту, не только на 443 — это специально,
  но иногда ловит лишнее
- если pcap большой (>500 МБ) — будет долго и жрать память, потому что читаю
  файл целиком. Потом переделать на чтение потоком
- тестировал пока только на синтетике, реальные захваты еще не гонял
